# Skill Proof review and fix status — 2026-10-12

## Fixed in this review

- Standalone MCP processes now read the same explicit embedding provider, model, gateway, model-directory, and vector-database settings from environment variables. An unconfigured process remains lexical-only and does not create a vector database as a side effect.
- Turn receipts and audit records distinguish the configured provider from the provider actually used, record fallback reasons, and include embedding latency. Missing gateway credentials are reported as `gateway_key_missing`.
- Explicit `$skill` requests skip catalog embedding synchronization, avoiding unnecessary vector work for a direct selection.
- `setup` now updates only `plugins.entries.skill-proof.settings`, preserves unrelated YAML content, and is idempotent. Local model prefetch requires an explicit `y` response or `--prefetch`; model download and checksum verification remain opt-in.
- The baseline inference test now skips when model files exist but optional runtime dependencies are unavailable. The checksum mock now exercises actual response bytes.
- README and changelog no longer claim a fixed prompt-token reduction.

## Open constraints

- The Hermes `pre_llm_call` hook used by this plugin can append context to the current user message, but cannot remove or rewrite Hermes' fixed `<available_skills>` system-prompt index. Skill Proof therefore cannot implement or claim that prompt reduction through this hook. The host integration would need a supported system-prompt filtering API.
- The registered model tokenizer inspected for this review is Unigram with Metaspace pre-tokenization, not WordPiece. A stdlib WordPiece tokenizer would produce incorrect inputs for this model. Supporting the current model requires the optional `tokenizers` package, or a separate model/spec choice.
- Local inference was not exercised in this environment because optional inference dependencies are unavailable. The test is skipped with that reason; gateway and lexical fallback behavior are covered by unit tests.
- Hermes plugin doctor validates discovery, manifest parsing, import, and hook registration. It does not prove behavior in a live Hermes conversation; that requires a restarted host and a live session.
